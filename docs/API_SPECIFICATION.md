## 1. Interface Architecture & Conventions (`PROPOSED`)

Consistent with `docs/ARCHITECTURE.md`, Slice 1 exposes two server entry surfaces:
1. **Next.js Server Actions (`src/server/actions/*`):** Used for all JSON-serializable workspace mutations invoked from React forms and interactive components.
2. **Next.js Route Handlers (`src/app/api/*`):** Used for Better Auth (`/api/auth/[...all]`), multipart binary PDF uploads, short-lived signed preview URLs, streaming Audit Packet exports, and TanStack Query paginated read endpoints.

### 1.1 Standard Response Envelopes (`PROPOSED`)
All **Server Actions** return a strict discriminated union:
```ts
type ActionResult<T> =
  | { ok: true; data: T }
  | {
      ok: false;
      error: {
        code: DomainErrorCode;
        message: string;
        fieldErrors?: Record<string, string[]>;
      };
    };
All JSON Route Handlers return:Success (200 / 201): { "data": <payload>, "meta"?: { ... } }Error (4xx / 5xx): { "error": { "code": "<DOMAIN_ERROR_CODE>", "message": "<safe human message>", "fieldErrors"?: { ... } } }1.2 Mandatory Execution PipelineEvery Server Action and Route Handler (except public auth routes) MUST execute in this exact order:Authenticate: Resolve Better Auth session (userId, activeTenantId). Return 401 UNAUTHORIZED if missing/expired.Validate Input: Parse request body/params with Zod. Return 400 VALIDATION_ERROR on failure.Authorize (src/server/policies/): Query live tenant_memberships (role, status = 'ACTIVE') inside withTenantContext(). Return 403 FORBIDDEN if unauthorized or 404 NOT_FOUND if resource does not belong to activeTenantId.Execute Service (src/server/services/): Run domain logic inside an atomic PostgreSQL transaction with SET LOCAL RLS context and row-level locks where required.Map Result: Return sanitized DTO (never expose raw database errors, stack traces, or internal storage keys).2. If lifecycle_state IN ('APPROVED', 'PUBLISHED', 'SUPERSEDED', 'RETIRED'): Returns 409 VERSION_IMMUTABLE (BR-VER-02).3.3 createRevisionAction (Server Action)Allowed Roles: WORKSPACE_ADMIN, QUALITY_MANAGER, DOCUMENT_AUTHOR   Zod Input (PROPOSED): { sourceVersionId: uuid; revisionType: "MAJOR" | "MINOR" }Behavior: Clones a PUBLISHED version into a new DRAFT version (parent_version_id = sourceVersionId), computing next semantic version (v1.0 → v2.0 or v1.1), and logs REVISION_CREATED.   3.4 POST /api/documents/[documentId]/versions/[versionId]/upload (Route Handler)Allowed Roles: WORKSPACE_ADMIN, QUALITY_MANAGER, DOCUMENT_AUTHOR   Request: multipart/form-data with field file (application/pdf, > 0 bytes and <= 50MB) + expectedRowVersion + optional confirmInvalidateApprovals.   Validation (REQ-FR-101, REQ-NFR-001):Verifies Content-Type AND inspects first 5 bytes for %PDF- magic header.Streams bytes through Node.js SHA-256 hasher to produce file_sha256 within the REQ-NFR-001 budget (< 1.5s up to 20MB; < 5s for 20–50MB).   Uploads binary to private Supabase Storage at tenants/{tenantId}/documents/{documentId}/versions/{versionId}/{uuid}.pdf.Updates document_versions. If the version is currently PENDING_APPROVAL, the same rule as updateDocumentVersionAction (§3.2) applies: if confirmInvalidateApprovals !== true, returns 409 INVALIDATION_CONFIRMATION_REQUIRED and uploads nothing; otherwise, inside a single FOR UPDATE transaction, applies DEC-04 invalidation (marks the active cycle/steps INVALIDATED, increments the draft revision, clears document_sha256, sets state to DRAFT, appends APPROVAL_INVALIDATED_BY_EDIT) and then stores the new PDF.   Response (201 Created): { data: { versionId, fileSizeBytes, fileSha256, lifecycleState, rowVersion } }3.5 GET /api/documents/[documentId]/versions/[versionId]/preview-url (Route Handler)Allowed Roles: All authenticated tenant roles subject to state visibility (Reader allowed ONLY when lifecycle_state === 'PUBLISHED'). Sequential Approval Workflow & Sign-Offs4.1 submitForApprovalAction (Server Action)Allowed Roles: WORKSPACE_ADMIN, QUALITY_MANAGER, DOCUMENT_AUTHOR   Zod Input (PROPOSED):TypeScript{
  versionId: uuid;
  expectedRowVersion: number;
  approverIds: uuid[]; // Ordered list (min 1, max 10, no consecutive duplicates)
}
Validation & Behavior:Verifies every approverId is an ACTIVE member in tenant_id with role in ('WORKSPACE_ADMIN', 'QUALITY_MANAGER', 'APPROVER_REVIEWER').   Enforces BR-APP-01 (DEC-03): rejects if approverIds includes version.author_id unless tenants.allow_single_author_override === true and no other approver exists.   Computes canonical document_sha256 (DEC-06), creates approval_cycles (IN_PROGRESS) and ordered approval_steps (step 1 = PENDING, steps 2..N = WAITING), transitions version to PENDING_APPROVAL, and appends WORKFLOW_SUBMITTED audit log.   4.2 executeApprovalDecisionAction (Server Action)Allowed Roles: WORKSPACE_ADMIN, QUALITY_MANAGER, APPROVER_REVIEWER (must match active PENDING step's assigned_approver_id).   Zod Input (PROPOSED):TypeScript{
  approvalStepId: uuid;
  decision: "APPROVE" | "REJECT";
  decisionIntent: string;       // Mandatory 5..1000 chars (REQ-FR-402)
  reauthPassword: string;       // Mandatory Slice 1 re-auth (REQ-FR-401)
}
Validation & Behavior (Atomic FOR UPDATE Transaction):Verifies reauthPassword via Better Auth (BR-SIG-01).   Verifies step is PENDING, cycle is IN_PROGRESS, version is PENDING_APPROVAL, and actor.id === step.assigned_approver_id (BR-SEQ-02).Enforces BR-APP-01 (DEC-03): rejects 403 SELF_APPROVAL_PROHIBITED if actor.id === version.author_id and cycle.allow_self_approval_override === false.   Server-side only: recomputes document_sha256 from the stored payload/metadata and verifies it === cycle.submitted_sha256 === version.document_sha256 (DEC-06); aborts with 422 INTEGRITY_HASH_MISMATCH on discrepancy. The client NEVER supplies a digest — `expectedDocumentSha256` is not an input to this action.   Records immutable sign-off metadata (acted_by_full_name, acted_by_role, acted_ip_address, acted_at, signed_document_sha256, decision_intent).   If APPROVE: activates next sequential step or transitions version to APPROVED if final step; logs APPROVAL_GRANTED (and DOCUMENT_APPROVED).If REJECT: closes cycle REJECTED, transitions version to DRAFT, and logs APPROVAL_REJECTED.4.3 recallApprovalAction (Server Action — PROPOSED)Allowed Roles: Submitting DOCUMENT_AUTHOR, QUALITY_MANAGER, WORKSPACE_ADMINZod Input: { versionId: uuid; expectedRowVersion: number; reason: string }Behavior: Atomically closes active cycle as RECALLED, marks collected steps INVALIDATED, returns version to DRAFT, and logs APPROVAL_RECALLED.4.4 adminOverrideApproverAction (Server Action — BR-APP-04)Allowed Roles: WORKSPACE_ADMIN ONLY   Zod Input (PROPOSED): { approvalStepId: uuid; newApproverId: uuid; justification: string }Behavior: Validates newApproverId is ACTIVE, has approval role, and satisfies BR-APP-01 (not document author); updates assigned_approver_id, records overridden_from_approver_id, and logs ADMIN_APPROVER_OVERRIDE.   5.
